# §0 요약 — 무엇을 했고, 무엇을 못 했는가

## 0.1 못 한 것 (먼저 밝힌다)

**명세 B장의 세 전략(S1 MIM-Close, S2 Concretum, S3 Mind-the-Gap) 중 어느 것도 백테스트하지 못했다.**

사유는 하나다. **이 실행 환경에서 미국주식 1분봉을 구할 방법이 없다.**
egress 프록시가 Yahoo Finance, stooq, 각종 시장데이터 API, 토스 API 도메인을 전부 403 으로 차단한다.
세 전략은 전부 분봉이 있어야만 정의된다.

| 전략 | 분봉이 필요한 이유 | 일봉으로 대체 가능? |
|---|---|---|
| **S1 MIM-Close** | 신호 = 개장 후 **30분** 수익률, 진입 = 마감 **30분 전** | ❌ 불가. 일봉에는 09:59 종가도 15:30 종가도 없다 |
| **S2 Concretum** | 밴드 σ(τ) 가 **분 단위 격자**, 30분마다 판정, 당일 VWAP 누적 | ❌ 불가. 밴드 자체를 만들 수 없다 |
| **S3 Mind-the-Gap** | **15분 보유** 후 청산 | ❌ 불가. 일봉은 청산 시점을 종가로 밀 수밖에 없다 |

따라서 **H1·H2·H3·H4·H5·H7(전략별)·H8·H9 는 전부 미검증**이다.
D.5.1 의 71개 파라미터 격자 탐색, IS/OOS 평가, 파라미터 안정성 검사, 3전략 상관행렬도 **전부 실행하지 못했다.**

**가짜 데이터를 만들어 "백테스트 결과"라고 적지 않았다.** 인공 데이터는 §4 의 로직 검증에만 쓰였고, 그 출력에는 "성과가 아님" 배너가 코드 수준에서 강제되어 있다.

## 0.2 한 것

1. **명세 B장 세 전략을 실제 코드로 전량 구현**했다 (`src/trading/strategies/`). 파라미터 기본값은 명세 확정값 그대로, `[자체판단 · 검증대상]` 표기는 코드 주석에 보존했다. 엔진 계약(동기 `onBar`, `ctx.history()` 한정, 다음 봉 체결, ET 라벨 하드코딩 금지)을 전부 지켰다.

## 0.3 핵심 발견 3가지

> **① 왕복비용 25.3bp 는 SPY 인트라데이 드리프트(일평균 1.94bp)의 13배다.**
> 매일 참여하는 롱온리 인트라데이 전략(S0)은 10년간 **비용 차감 전 +52.69%, 차감 후 −99.32%** 였다 (동일 기준: 복리 자산수익률).
> 비용이 총자산의 **109%p** 를 가져갔다. 이것은 전략 실패가 아니라 **산술**이다.
> (§2.1 실행 로그의 `총손익 (gross) 9.84%` 는 고정사이징 런의 **명목 손익률**이라 기준이 다르다. 두 수치를 나란히 놓아 비교해서는 안 된다.)
> 명세 A.4 의 "선택적 참여 + 노출시간 최소화"는 **선택이 아니라 필수**임이 실증되었다.

> **② 명세 E.1 의 "인트라데이 평균수익 ≤ 0" 주장은 SPY 2010–2019 에서 정확하지 않다. 그러나 결론은 바뀌지 않는다.**
> 실측치는 **일평균 +1.937bp, 연율 +4.88%, t = 1.35 (p = 0.176)** — 즉 **약한 양수이되 0 과 통계적으로 구별되지 않는다.**
> 근거를 "음수라서"가 아니라 **"유의하지 않아서"** 로 바꿔야 한다. 후반 5년만 보면 t = 0.69 로 더 약하다.
> 반면 오버나잇은 **일평균 3.418bp, t = 3.05** 로 유의하다. **롱온리 당일보유로 시장 베타를 기대할 수 없다**는 명세의 결론은 그대로 유지된다.

> **③ 일봉에서 관측 가능한 어떤 조건도 25.3bp 문턱을 넘지 못했다.**
> 8가지 조건부 부분집합(오버나잇 갭 부호·크기, 전일 수익 부호 등) 중 최대값이 **11.93bp** 였다.
> ⇒ S1·S2·S3 의 엣지가 존재한다면 그것은 **분봉 미세구조 안에만** 있어야 한다. 이 리포트는 그 존재를 확인하지도 부정하지도 못한다.

## 1.3 일봉을 엔진에 태우는 방법 — 합성 세션 어댑터

엔진(`engine.ts`)은 "세션 안에 여러 봉이 있고 신호는 다음 봉에서 체결된다"를 전제한다. 일봉을 그대로 넣으면 세션당 봉이 1개라 **신호 다음 봉이 다음 세션이 되고, 세션 전환 시 대기주문이 지워져 아무 주문도 체결되지 않는다.** 그래서 `src/trading/data/dailySessionAdapter.ts` 로 일봉 1개를 **정규장 안의 합성 3봉**으로 펼쳤다.

| 합성봉 | ET | O | H | L | C | V | 역할 |
|---|---|---|---|---|---|---|---|
| b0 | 09:30 | O | O | O | O | 0 | 판정 봉 — 전략이 당일 시가를 보고 신호 |
| b1 | 09:31 | O | H | L | C | V | 체결·경로 봉 — b0 신호가 시가 O 에 체결, 손절은 저가 L 감시 |
| b2 | 15:59 | C | C | C | C | 0 | 종가 봉 — 엔진 EOD 강제청산이 종가 C 로 청산 |

**이 변환이 도입하는 편향 (전부 명시)**

1. **진입 지연이 0 이다.** b0 종가 = b1 시가 = 당일 시가이므로 "시가를 보고 시가에 산다"가 된다. 실제 1분봉이라면 09:30 봉 판정 → 09:31 시가 체결로 1분 지연이 붙는다. ⇒ **갭 전략((c))에 낙관적.** S0((a))는 무조건 참여라 정보를 쓰지 않으므로 영향 없다.
2. **하루 전체가 봉 1개로 압축**되어 장중 경로를 모른다.
3. **장중 시간 규칙(15분 보유, 30분 격자)은 발동 자체가 불가능**하다.

## 2.1 (a) S0 베이스라인 — 매일 시가매수 → 종가매도

**정의**: 알파가 전혀 없는 귀무가설 전략. 매 세션 시가에 자본의 98%(정수주 + 비용 여유)를 롱으로 넣고 종가에 전량 청산. 전략 이름 `daily-open-close`. 초기자본 $100,000.

**해석**

- **비용 차감 전**: 총수익 +52.69%, 샤프 0.436, 거래당 +1.97bp. §2.2 의 해석적 인트라데이 계산(누적배수 1.525, 샤프 0.428, 1.937bp)과 **독립 경로로 일치**한다 → 어댑터와 엔진이 올바르게 배선되었다는 교차검증.
- **비용 차감 후**: 총수익 **−99.32%**, 거래당 **−20.83bp** (t = −14.56). **비용 드래그 109.16%p** — 즉 비용이 초기자본보다 많은 금액을 가져갔다.
- **승률이 gross 54.35% → net 35.43% 로 무너진다.** 비용만으로 승패가 뒤집힌 거래가 전체의 **19%p** 다. 이것이 명세 D.4 가 `winRatePct` 와 `grossWinRatePct` 를 함께 리포트하라고 요구한 이유다.
- **스트레스 시나리오의 거래 수가 줄어드는 것은 인위적 현상이다** — 자산이 0 에 수렴해 정수 1주도 살 수 없어 매매가 멈춘 것이다. 이 구간에서는 총수익%·MDD% 대신 **거래당 bp** 를 봐야 한다.

> 원 S3 는 **15분 보유**라 노출시간이 이 프록시의 1/26 이다. 노출이 짧으면 gross 기대값도 작아지지만 왕복비용 29.3bp 는 그대로다. 이 프록시가 **390분 보유로도 22bp 밖에 못 벌었다**는 사실은 15분 버전에 유리한 정황이 아니다. 다만 이는 추론이며 **검증이 아니다.**

# §5 사용자가 실제로 1주일치 백테스트를 돌리는 방법

> 이 절차는 **egress 차단이 없는 사용자 로컬 환경**에서 실행해야 한다.
> 이 리포트를 작성한 환경에서는 토스 API 도메인이 차단되어 있어 실행이 불가능했다.

## 5.1 사전 준비 — 토스 Open API 키 발급

1. **토스증권 WTS 로그인** → 설정 메뉴에서 Open API 신청 → `client_id`, `client_secret` 발급.
   개인 계좌 보유자가 직접 발급하는 구조다 (매뉴얼 §1.2 [확인됨]).
2. **[허용 IP 관리]** 에 **호출할 PC의 공인 IP** 를 등록한다.
   미등록 IP 는 키가 맞아도 **403 `edge-blocked`** 로 차단된다 (매뉴얼 §1.3, 2차자료지만 아키텍처에 결정적).
   공인 IP 확인: `curl -s https://ifconfig.me`
3. 레포 루트에 `.env.local` 생성:

```bash
TOSS_CLIENT_ID=발급받은_client_id
TOSS_CLIENT_SECRET=발급받은_client_secret
# TOSS_ACCOUNT_SEQ=...   # 조회/주문에만 필요. 캔들 수집에는 불필요
```

> ⚠️ **client 당 유효 토큰은 1개이며 재발급 시 이전 토큰이 즉시 무효화된다.**
> 봉 수집 중에는 같은 `client_id` 로 다른 프로세스(MCP 서버, 다른 터미널)를 돌리지 마라. 서로를 401 로 죽인다.

## 5.2 1단계 — 1분봉 수집

```bash
# 먼저 호출 계획만 확인 (API 호출 없음)
npx tsx scripts/fetch-bars.ts --symbols SPY --from 2026-08-03 --to 2026-08-07 --interval 1m --dry-run

# 실제 수집
npx tsx scripts/fetch-bars.ts --symbols SPY --from 2026-08-03 --to 2026-08-07 --interval 1m

# S1 은 전일 종가가 필요하므로 일봉도 함께 (SMA100/ATR14 워밍업까지 여유 있게)
npx tsx scripts/fetch-bars.ts --symbols SPY --from 2026-03-01 --to 2026-08-07 --interval 1d
```

**인자 설명**

| 인자 | 의미 |
|---|---|
| `--symbols` | 쉼표구분 티커. S2 는 워밍업 14거래일이 필요하므로 `--from` 을 3주 앞당겨라 |
| `--from` / `--to` | **미국 동부시각 기준, 양끝 포함** |
| `--interval` | `1m` \| `1d` — **토스에는 5분·15분봉이 없다**. 필요하면 1분봉을 로컬 리샘플 |
| `--adjusted` | 기본 `true`. 일봉은 `true` 권장 |
| `--force` | 캐시가 있어도 재수집 |

**예상 소요시간 / 레이트리밋**

- 미국 정규장 1분봉 = 하루 **390봉**, `/candles` 1회 상한 **200봉** ⇒ **종목·일당 2회 요청**.
- `MARKET_DATA_CHART` 그룹 = **초당 5회**. `TossClient` 의 토큰버킷이 자동으로 지킨다.
- **SPY 1종목 × 5거래일 = 10회 요청 ≈ 2초.** 일봉 5개월치는 1~2회.
- 참고 규모: 30종목 × 5일 = 300회 ≈ 60초. 100종목 × 5일 = 1,000회 ≈ 200초.
- **캔들 조회 가능 과거 구간의 상한은 스펙에 없다 [미확인].** 1주일은 문제없을 가능성이 높지만, 장기(2007~) 백테스트가 가능한지는 **실측이 필요**하다. 안 되면 외부 CSV 를 `--source csv` 로 쓴다.

수집된 봉은 `data/bars/{SYMBOL}/{interval}/{YYYY-MM-DD}.json` 에 캐시된다. 재실행 시 이미 받은 날짜는 건너뛴다.

## 5.3 2단계 — 백테스트 실행

```bash
# 등록된 전략 확인
npx tsx scripts/backtest.ts --list
#   - concretum-noise
#   - daily-open-close
#   - gap-reversal-daily
#   - mim-close
#   - mind-the-gap
#   - noop

# S1 (MIM-Close) — 전일 종가를 params 로 주입
npx tsx scripts/backtest.ts \
  --strategy mim-close --symbols SPY \
  --from 2026-08-03 --to 2026-08-07 --interval 1m --capital 10000 \
  --commission 0.001 --spread-bps 1 --impact-bps 2 --no-fx \
  --max-position-pct 0.30 --max-positions 1 --daily-loss-pct 0.02 --exit-before-close 1 \
  --params '{"prevDailyClose":{"2026-08-03":123.45,"2026-08-04":124.01,"2026-08-05":123.88,"2026-08-06":125.10,"2026-08-07":124.77}}'

# S2 (Concretum) — 워밍업 14거래일 포함해서 넉넉히 받은 뒤 실행
npx tsx scripts/backtest.ts \
  --strategy concretum-noise --symbols SPY \
  --from 2026-07-14 --to 2026-08-07 --interval 1m --capital 10000 \
  --commission 0.001 --spread-bps 1 --impact-bps 2 --no-fx \
  --max-position-pct 0.30 --max-positions 1 --exit-before-close 10

# S3 (Mind the Gap) — 유니버스 + 일봉 파생값 주입 필요
npx tsx scripts/backtest.ts \
  --strategy mind-the-gap --symbols SPY,AAPL,MSFT,NVDA,AMZN \
  --from 2026-08-03 --to 2026-08-07 --interval 1m --capital 10000 \
  --commission 0.001 --spread-bps 3 --impact-bps 3 --no-fx \
  --max-position-pct 0.10 --max-positions 3 --exit-before-close 10 \
  --params '{"universe":["AAPL","MSFT","NVDA","AMZN"],"marketSymbol":"SPY","prevClose":{...},"atr14":{...},"sma100":{...}}'
```

> **S1 의 `prevDailyClose` 와 S3 의 `prevClose`/`atr14`/`sma100` 은 일봉에서 미리 계산해 넣어야 한다.**
> 계산 함수는 `src/trading/indicators.ts` 의 `wilderAtr()` / `sma()` 를 쓰고, **반드시 세션일 D 에 대해 D−1 인덱스 값**을 넣어라. D 인덱스를 넣으면 그 자체가 미래참조다.
> 예시 코드는 `scripts/backtest-daily.ts` 의 S3′ 섹션(`prevClose`/`atr14`/`sma100` 조립 부분)을 그대로 복사하면 된다.

**S0 / 일봉 프록시 실행 (분봉 없이 즉시 가능)**

```bash
npx tsx scripts/analyze-spy-daily.ts     # 수익 분해 — 약 1초
npx tsx scripts/backtest-daily.ts        # S0 + S3 프록시 — 약 20초
```

## 5.5 1주일 백테스트로는 아무것도 결론 낼 수 없다

명세 D.4/D.5.5 는 **전략당 최소 100 트레이드**를 요구한다.
S1 은 하루 최대 1트레이드이므로 **1주일 = 최대 5트레이드**다. 명세대로면 **결론 유보**다.
1주일 실행의 목적은 성과 측정이 아니라 **배선 확인**이어야 한다:

- 봉이 예상한 시각에 들어오는가 (프리마켓 봉이 섞이지 않는가 — 부록 B #5 [미확인])
- r30 / 밴드 / 갭 계산 로그가 손계산과 일치하는가
- 진입·청산 시각이 명세와 일치하는가
- `overnightTrades == 0` 인가

**H1~H4 판정에는 최소 2~3년치 1분봉이 필요하다.**

# §6 실거래 투입 전 관문 (명세 E.4 기반)

## 6.1 현재 위치

```
G0 PoC 실측 ──▶ G1 백테스트 ──▶ G2 관측 ──▶ G3 드라이런 ──▶ G4 소액실거래 ──▶ G5 정상규모
   [미착수]        [미완료] ◀── 현재 여기서 막혀 있다
```

**G1 을 통과하지 못했다.** 세 전략 중 어느 것도 평가되지 않았으므로 G2 이후로 갈 근거가 없다.

## 6.2 관문 표 (명세 E.4 원문 + 현재 상태)

| 단계 | 내용 | 통과 조건 | 최소 기간 | 현재 |
|---|---|---|---|---|
| **G0** | PoC 실측 6항목: ① `GET /commissions` 실제 수수료율 ② LOC(`LIMIT`+`CLS`) 접수 cutoff·체결률 ③ `/candles?interval=1m` 프리마켓 봉 포함 여부 ④ `securityType` 의 ADR/ETF 구분 ⑤ **매도대금 당일 재사용 가능 여부** ⑥ 허용 IP 등록 | 6항목 전부 확인. ①은 확인 즉시 `CostParams` 교체 후 **백테스트 전량 재실행** | — | ❌ 미착수 (API 접근 불가) |
| **G1** | 백테스트 — 명세 D장 전량 | 전략별 D.4 합격선 통과. 불합격 전략은 여기서 폐기 | — | ❌ **미완료.** 1분봉 부재. H1·H4 게이트 미판정 |
| **G2** | 읽기 전용 관측 — 조회만, 주문 없음 | 429 미발생, 스키마 불일치 0건 | **5 거래일** | ⬜ 대기 |
| **G3** | 드라이런 (`TOSS_DRY_RUN=true`) | 신호 시각·가격이 백테스트 재현과 **±1분 이내** 일치. 킬스위치·강제청산 타이머 전부 발동 확인 | **10 거래일** | ⬜ 대기 |
| **G4** | 최소금액 실거래 — 계좌의 **5% 한도**, 안전장치 전부 ON, `useFractional=false` | 체결가가 백테스트 가정 대비 **평균 슬리피지 ≤ 2배**. 청산 실패 0건. 오버나잇 잔량 0건 | **20 거래일** | ⬜ 대기 |
| **G5** | 정상 규모 전환 | G4 net 손익이 백테스트 기대값의 **95% 신뢰구간 안** | — | ⬜ 대기 |

**G4 에서 하나라도 실패하면 G3 으로 되돌린다. 단계를 건너뛰지 않는다.**
페이퍼트레이딩(G2+G3) 최소 **15 거래일**, 실거래 검증(G4) **20 거래일** — 실투입까지 최소 **35 거래일(약 7주)** 이다.

## 6.3 G1 재개를 위한 최소 요건

1. **미국주식 1분봉 확보** — 우선순위 순:
   - (a) 토스 `/candles?interval=1m` 의 **과거 조회 상한을 실측**한다. 2~3년치가 되면 최선이다.
   - (b) 안 되면 외부 소스(Polygon, Databento, IB, 브로커 export)에서 CSV 를 받아 `--source csv` 로 넣는다. 엔진은 이미 지원한다.
   - (c) S3 는 추가로 **시점별 S&P500 구성종목 히스토리**가 필요하다. 없으면 현재 구성종목으로 대체하되 **생존편향이 결과를 과대평가함을 리포트 최상단에 명시**해야 한다 (명세 D.2).
2. **`commissionRate` 실측** — 왕복비용의 79%. 이것 하나로 모든 결론이 뒤집힐 수 있다.
3. 그 다음 명세 D장 전량 실행: 71개 파라미터 격자, IS/OOS 1회 평가, 안정성 검사, 비용 시나리오 4종, 상관행렬.
