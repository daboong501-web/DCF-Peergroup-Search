## 0. 결론 먼저

**단일종목·국내 ETF 로 옮기면서 미국 설계의 3대 난점 중 2개가 사라지고, 1개가 새로 생겼다.**

| | 미국주식 (SPY 등) | 229200 | 판정 |
|---|---|---|---|
| 종목 스크리닝 | 스크리너 API 부재가 최대 병목 | **단일종목이라 스크리닝 자체가 불필요** | ✅ 해소 |
| 거래비용 | 왕복 25.29bps | **왕복 6.38bps** | ✅ 3.96배 개선 |
| 확정적 종가청산 | LOC(`LIMIT`+`CLS`) 사용 가능 | **LOC 사용 불가 (미국 전용)** | ❌ 새 난점 |

가장 중요한 변화는 **비용**이다. 미국 백테스트(`03-backtest-report.md`)의 핵심 발견은
"왕복비용 25.3bps 가 SPY 인트라데이 드리프트(1.94bps)의 13배라 매일 참여하면 산술적으로 진다"는 것이었다.
229200 은 그 비용이 **6.38bps** 이고, 기초지수인 KOSDAQ150 은 SPY 보다 변동성이 훨씬 크다.
**신호 대비 비용비가 근본적으로 다른 게임**이므로 미국 결론을 그대로 옮기면 안 된다.

다만 **비용이 싸졌다는 것이 곧 수익이 난다는 뜻은 아니다.** 이 문서는 명세이지 수익 약속이 아니다.

## 2. 비용 구조 — 이 시스템의 핵심 우위

### 2.1 왕복비용 산식

`src/trading/krCosts.ts` 의 `krEtfCostParams()` 가 계산한다. 가격 14,780원 기준:

| 항목 | 값 | 근거 |
|---|---|---|
| 위탁수수료 (편도) | 0.015% = **1.50bps** | [2차자료] 토스 국내주식 KRX 0.015% / NXT 0.014%. **`GET /api/v1/commissions` 실측 필요** |
| 증권거래세 (매도) | **0** | [2차자료] ETF 는 증권거래세 면제 |
| 양도소득세 | **0** | [2차자료] 국내주식형 ETF 매매차익 비과세 |
| 환전 스프레드 | **0** | 원화 거래 |
| 호가 1틱 | 5원 = **3.38bps** | 5 / 14,780 |
| 스프레드 (1틱 가정) | 3.38bps, 시장가는 절반 부담 | [자체판단 · 검증대상] |

**왕복 = half-spread 1.69 × 2 + 수수료 1.50 × 2 = 6.38bps**

### 2.2 스프레드가 벌어질 때

1틱 가정은 낙관적일 수 있다. LP(유동성공급자)가 붙는 ETF라 평시엔 1틱이지만
장 초반·마감 무렵·급변 구간에서는 벌어진다.

| 스프레드 | 왕복비용 | 비고 |
|---|---|---|
| 1틱 | 6.38bps | 평시 가정 |
| 2틱 | 9.77bps | 변동성 확대 |
| 3틱 | 13.15bps | 장 초반 / 급변 |

**3틱까지 벌어져도 미국 SPY(25.29bps)의 절반이다.** 비용 우위는 견고하다.

### 2.3 미국과의 대조

```
229200 왕복 :  6.38 bps
SPY    왕복 : 25.29 bps   →  3.96배 저렴
```

## 3. 하락 방향은 비싸다 — 반드시 인지할 비대칭

토스 API 는 **공매도가 불가능**하다 (`side` enum = `["BUY","SELL"]` 뿐) [확인됨, 스펙 v1.1.1].
하락에 베팅하려면 **인버스 ETF 를 롱**하는 수밖에 없다. 그런데 비용이 전혀 다르다:

| 종목 | 가격 | 1틱 | 왕복비용 |
|---|---|---|---|
| 229200 (정방향) | 14,780원 | 3.38bps | **6.38bps** |
| 251340 (인버스) | 2,310원 | 21.65bps | **24.65bps** |

**인버스가 3.86배 비싸다.** 호가 단위가 똑같이 5원인데 가격이 6.4배 낮아서 생기는 순수한 구조적 불이익이다.

⇒ **설계 원칙**: 상승 신호와 하락 신호에 **같은 문턱을 쓰면 안 된다.**
하락 진입은 기대수익이 최소 24.65bps 를 넘어야 하므로 문턱을 훨씬 높게 잡거나, 아예 롱 온리로 가라.
1차 구현은 **229200 롱 온리**를 권고한다.

> 참고: 251340 이 2,000원 밑으로 내려가면 호가 단위가 1원이 되어 왕복비용이 8.13bps 로 급락한다.
> 가격대에 따라 전략 성립 여부가 뒤집히므로, 인버스를 쓸 거면 **호가 단위를 가격에서 동적으로 계산**해야 한다.
> `krEtfCostParams({ referencePrice, tickSize })` 가 이를 지원한다.

## 4. 미국 설계가 그대로 넘어오지 않는 부분

### 4.1 LOC 를 쓸 수 없다 ← 가장 큰 변경

스펙 원문: *"`CLS`: 장 마감 주문 (At the Close). 현재 **미국 주식 + `orderType=LIMIT` 조합만** 지원합니다."* [확인됨, 스펙 v1.1.1]

미국 설계는 LOC 로 **확정적 종가청산**을 걸었다. 국내는 그 수단이 없다.
⇒ **접속매매 시간 안에 봇이 직접 청산해야 한다.**

### 4.2 종가 단일가 + 랜덤엔드

국내 정규장은 미국과 구조가 다르다:

| 구간 | 시각 (KST) | 성격 |
|---|---|---|
| 장 시작 동시호가 | 08:30~09:00 | 단일가 |
| **접속매매** | **09:00~15:20** | 연속체결 — 봇이 자유롭게 매매 가능 |
| **종가 단일가** | **15:20~15:30** | 호가 접수 후 15:30 에 한 가격으로 일괄체결 |
| 정규장 종료 | 15:30 | **랜덤엔드로 최대 30초 늦춰질 수 있음** |

**랜덤엔드** 때문에 마감 시각을 초 단위로 신뢰하면 안 된다.
그리고 15:20 이후에는 연속체결이 없어서 "지금 시장가로 던져 즉시 빠져나온다"가 성립하지 않는다.

⇒ **청산 정책: 15:15 에 접속매매로 전량 청산** (단일가 시작 5분 전).
`KrRegularSessionCalendar` 의 기본 `exitBeforeCloseMinutes = 15` 가 이 값이며,
**10분 미만으로 설정하면 생성자가 예외를 던져 거부한다** (단일가 구간에 걸리므로).
`scripts/test-kr.ts` [D] 에서 검증한다.

### 4.3 서머타임이 없다

KST 는 연중 UTC+9 고정이라 미국 설계의 DST 처리가 통째로 불필요하다.
`krSession.ts` 는 고정 오프셋을 쓰고, 테스트 [A] 가 1월/8월 오프셋 동일성을 검증한다.

### 4.4 공휴일은 규칙으로 유도 불가

한국 공휴일은 음력·대체공휴일·임시공휴일 때문에 계산할 수 없다.
백테스트는 봉이 없는 날을 자연히 건너뛰지만, **실거래는 반드시 `GET /api/v1/market-calendar/KR` 을 써라.**

### 4.5 NXT(대체거래소) 때문에 "장 마감"이 모호하다

넥스트레이드 출범으로 08:00~20:00 거래가 가능하고,
토스의 `market-calendar/KR` 은 **"통합 모드(KRX+NXT) 기준"** 이라고 스펙에 명시돼 있다 [확인됨].

⇒ 캘린더 응답을 그대로 "정규장"으로 쓰면 **15:30 이후에도 장이 열려 있다고 오판**할 수 있다.
당일청산 기준 시각은 **KRX 정규장 15:30 으로 고정**하고, 캘린더는 휴장일 판정에만 쓰라.
`GET /api/v1/stocks` 의 `koreanMarketDetail.nxtSupported` 로 NXT 취급 여부를 확인할 수 있다 [확인됨].

### 4.6 상하한가가 있다

미국은 `upperLimitPrice` 가 null 이지만 국내는 ±30% 제한이 실재한다.
`GET /api/v1/price-limits` 로 받아 **지정가가 범위를 벗어나지 않게** 검증하라.

### 4.7 호가 단위를 어기면 주문이 거부된다

스펙: *"KR: 정수(원 단위). 호가 단위에 맞아야 합니다. 맞지 않으면 `400 invalid-request`"*,
에러 응답 `data` 에 `tickSize` 와 `nearestPrices[lower, upper]` 가 담긴다 [확인됨].
⇒ 지정가는 반드시 5원 배수로 내라. `roundToTick()` 이 **항상 불리한 방향**(매수 올림/매도 내림)으로
맞춰 낙관적 체결을 차단한다.

## 7. 백테스트 — 무엇을 검증해야 하는가

### 7.1 데이터

**이 실행 환경에서는 229200 의 과거 분봉을 구할 수 없다.**
컨테이너의 egress 프록시가 `finance.naver.com` 을 포함한 모든 시장데이터 호스트를 차단한다.
(원격 MCP 는 Naver 에 닿지만 노출된 툴이 현재가만 주고 OHLCV 이력을 주지 않는다.)

⇒ 실데이터는 **사용자 환경에서 토스 API 로** 받아야 한다:

```bash
npx tsx scripts/verify-toss.ts                                    # 연결·수수료 실측
npx tsx scripts/fetch-bars.ts --symbols 229200 --interval 1m --days 7
```

### 7.2 반드시 사전에 못박을 것

미국 명세(`02-strategy-spec.md` D장)의 규율을 그대로 승계한다:

- **합격선을 먼저 정하고 사후에 완화하지 않는다.**
- IS/OOS 분리, 파라미터 탐색 범위 상한, 최소 표본 거래수.
- **손익분기 문턱**: 왕복 6.38bps. 거래당 기대수익이 이를 못 넘으면 그 전략은 폐기다.
  스프레드 2~3틱 스트레스(9.77 / 13.15bps)에서도 부호가 유지되는지 반드시 확인하라.

### 7.3 이 종목에 고유한 검증 항목

| # | 가설 | 왜 중요한가 |
|---|---|---|
| K1 | 1분봉에 **장전 동시호가(08:30~09:00) 봉이 섞이는가** | 섞이면 시가·갭 계산이 전부 틀어진다. `verify-toss.ts` 로 실측 |
| K2 | 15:20~15:30 단일가 구간의 봉이 어떻게 나오는가 | 청산 로직의 전제 |
| K3 | 실제 스프레드가 1틱인가 (시간대별) | 비용 가정의 근간. `orderbook` 으로 샘플링 |
| K4 | LP 호가가 얇아지는 시간대가 있는가 | 장 초반/마감 슬리피지 |
| K5 | ETF 괴리율(NAV 대비)이 인트라데이에 어떻게 움직이는가 | 지수 추종 가정의 신뢰도 |
| K6 | KOSDAQ150 인트라데이 드리프트가 0과 구별되는가 | 미국 SPY 는 t=1.35 로 구별 불가였다. **국내는 다를 수 있고, 이것이 전략 성립의 근본 전제다** |

**K6 가 최우선이다.** 미국에서 우리는 "인트라데이 드리프트가 유의하지 않다"는 것을 실데이터로 확인했다.
국내 KOSDAQ150 에 대해 같은 검증을 하기 전까지, 어떤 전략도 근거가 없다.

## 8. 현재 구현 상태

| 구성요소 | 상태 |
|---|---|
| KRX 세션 캘린더 (`krSession.ts`) | ✅ 구현·검증 (단일가 구분, 랜덤엔드 대비, 청산시각 방어) |
| 국내 ETF 비용모델 (`krCosts.ts`) | ✅ 구현·검증 (호가단위 반올림, 거래세 0, 동적 틱) |
| 호가단위 반올림 (`roundToTick`) | ✅ 항상 불리한 방향 |
| 백테스트 엔진 | ✅ 기존 엔진 재사용 (26개 검증, 회귀 없음) |
| 테스트 | ✅ **총 98개 통과** (엔진 26 + 전략 34 + KR 38) |
| **전략 로직** | ⬜ **미구현 — K6 검증 후에 정한다** |
| **실데이터 백테스트** | ⬜ **미실행 — 데이터 조달 필요** |

**전략을 먼저 짜지 않은 것은 의도적이다.**
미국 사례에서 우리는 "그럴듯한 전략을 먼저 고르고 나중에 검증했더니 전부 미검증으로 남는" 경로를 이미 겪었다.
229200 은 **K6(인트라데이 드리프트 존재 여부)를 실데이터로 먼저 확인하고**, 그 결과에 맞는 전략을 고르는 순서가 맞다.

## 9. 알려진 한계

- 수수료·호가단위·거래세 면제는 전부 **[2차자료]** 다. `commissions` API 와 실제 주문으로 검증하기 전까지 가정이다.
- 스프레드 1틱은 **[자체판단]** 이다. `orderbook` 샘플링으로 실측해야 한다.
- KOSDAQ150 은 SPY 보다 변동성이 크다 = 기대수익도 크지만 **손실 꼬리도 두껍다.** 비용이 싸다고 위험이 준 것이 아니다.
- ETF 는 지수를 완벽히 추종하지 않는다 (괴리율·추적오차). 단타 구간에서는 LP 호가에 좌우된다.
- 국내주식형 ETF 매매차익 비과세는 **현행 세법 기준**이며, 금융투자소득세 관련 제도 변경 시 전제가 무너진다.
