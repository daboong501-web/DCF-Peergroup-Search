### A.3.1 공매도 전제 방법론 일괄 기각 [확인됨, 스펙 v1.1.1]

## A.4 구조적 역풍에 대한 정면 답변

### A.4.1 문제의 정확한 진술

Lou, Polk & Skouras (JFE 2019) 및 관련 연구: **미국주식 장기수익의 거의 전부가 오버나잇 구간에서 발생하고, 평균 인트라데이 수익은 0 또는 음수다.** 당일청산 전략은 정의상 인트라데이 구간만 취한다.

⇒ **롱온리 당일청산은 시장 베타로 벌 수 없다.** 이것은 선택의 문제가 아니라 우리 시스템의 물리 법칙이다.

### A.4.2 봉쇄된 경로 — 롱/숏 양방향

**원천 봉쇄.** A.3.1의 스펙 확인 결과에 따라 "숏으로 음의 인트라데이 드리프트를 수확한다"는 정공법은 **선택지가 아니다.**

### A.4.3 검토했으나 1차 범위에서 **기각**한 우회로 — 인버스 ETF 롱

하락 방향 신호를 수확하는 유일한 우회로는 인버스 ETF(SH, PSQ, SDS, SQQQ 등) 롱 매수다. **명시적으로 판단한 결과 1차 실거래 범위에서 기각한다.**

| 축 | 판단 |
|---|---|
| 변동성 손실(volatility decay) | **문제 아님.** 일간 리밸런싱형의 경로의존 손실은 보유가 하루 미만이면 영향이 미미하다 → 이 사유로는 기각하지 않는다 |
| 유동성·스프레드 | SH/PSQ 는 SPY 대비 거래대금이 수십 분의 1이라 왕복 스프레드가 SPY(1bp)보다 확실히 넓다. 그러나 **정확한 값은 [미확인]** |
| 토스 취급 여부 | **[미확인]** — `GET /api/v1/stocks?symbols=SH,PSQ,SDS,SQQQ` 로 PoC 확인 필요 |
| 전략적 필요성 | **현재 없음.** 채택한 S1/S2/S3 중 어느 것도 "하락 방향 신호"를 주력 수익원으로 쓰지 않는다. S1의 음수 신호일은 **미진입**으로 처리한다 |
| **결론** | **1차 실거래 범위 제외.** 단 **백테스트 가설 H5 로 정량 검증**하여, 인버스 ETF 경로가 net Sharpe 를 유의하게 개선하지 못하면 **영구 폐기**한다 |

### A.4.4 채택한 답 — 선택적 참여(Selective Participation) + 노출시간 최소화

역풍이 작용하는 것은 **"시장에 노출된 시간"** 이다. 따라서 답은 두 축의 곱을 최소화하는 것이다.

```
실효 노출(effective exposure) = 진입일 비율(participation rate) × 일중 평균 노출시간 비율
```

정규장은 390분이다. 각 전략의 실효 노출은 다음과 같이 **산술로 결정된다**:

| 전략 | 진입일 비율 | 일중 노출 | 실효 노출 | 노출 시간대의 성격 |
|---|---|---|---|---|
| **S1** | r30 > θ 인 날만 (**백테스트 실측 필수**, 대칭성으로 ≈50% 예상) | **30분 / 390분 = 7.7%** | **≈ 3.9%** | 마감 30분 — 학술적으로 **평균 유의한 양(+)의 수익 구간** (Örebro WP 14/2025) |
| **S2** | 밴드 이탈일만 (**실측 필수**) | 진입~청산 (**실측 필수**) | **실측 필수** | 10:00~15:00, **점심(11:30~13:30 ET) 배제** — 신호 품질 최악 구간을 회피 |
| **S3** | 갭다운 > 1.2×ATR 발생일만 (**실측 필수**, 희소할 것) | **15분 / 390분 = 3.8%** | **실측 필수** | 개장 15분 — 정보 소화 구간, 변동성 최고 |

**논리의 핵심**: 평균 인트라데이 수익이 0 이하라는 것은 **분포의 1차 모멘트**에 대한 진술이다. 조건부 부분집합에서 양의 기대값이 존재할 수 있는가는 별개의 실증 문제이고, Gao et al. 의 "첫 30분 → 마지막 30분" 예측력(기울기 6.94, p<1%)이 **정확히 그 형태의 조건부 신호**다. 신호가 없는 날은 **아예 진입하지 않는 것이 전략의 일부**이며, "매일 거래한다"는 가정은 명시적으로 버린다.

**⚠ 이것은 가설이지 사실이 아니다.** Gao et al. 의 **R² = 1.6%** 는 예측력의 경제적 크기가 작다는 뜻이고, 거래비용이 이 엣지를 잡아먹을 수 있다. 그래서 D장의 H1(비용차감 후 기대값 > 0)이 **전 시스템의 게이트**다.

### A.4.5 참여율은 1급 파라미터다 — 강제 리포팅 규칙

3번 에이전트는 백테스트 결과에 다음을 **반드시 포함**해야 한다.

| 리포트 항목 | 정의 | 경보선 |
|---|---|---|
| `participationRate` | 진입이 1건 이상 발생한 거래일 수 / 총 거래일 수 | **S1 > 0.60 이면 경보** [자체판단 · 검증대상] — "선택적 참여" 논리가 무너졌다는 신호 |
| `effectiveExposure` | Σ(포지션 보유 분) / (거래일 수 × 390분) | **> 0.15 이면 경보** [자체판단 · 검증대상] — 역풍을 정면으로 맞고 있다 |
| `timeInMarketPnl` | 실효 노출 1%p 당 net 손익 | 음수면 전략이 역풍의 순수 피해자 |

### B.1.2 파라미터 확정표

**자유 파라미터는 `THETA_LONG`, `STOP_PCT` 2개뿐이다.** (사이징은 리스크 정책이지 알파 파라미터가 아니다.)

### B.1.3 진입/청산 의사코드

```
전략명: "mim-close"  ·  interval: "1m"  ·  symbols: ["SPY"]
init() 주입: prevDailyClose[date]   // 전일 일봉 종가 (adjusted=true)

onSessionStart(session):
    r30      = null       // 첫 30분 수익률
    decided  = false      // 당일 판정 완료 여부

onBar(bar, ctx):
    et = etTimeLabel(bar.t)                      // session.ts 의 ET 라벨 (HH:MM)

    // ── (1) 첫 30분 수익률 확정: 09:59 봉 종가 = 개장 후 30분 경과 시점
    if et == "09:59" and r30 == null:
        r30 = bar.c / prevDailyClose[ctx.session.date] - 1
        ctx.log(`[S1] r30 = ${(r30*100).toFixed(3)}%`)
        return null

    // ── (2) 진입 판정: 마감 30분 전 봉에서 단 1회
    if et == "15:30" and not decided:
        decided = true
        if r30 == null:
            ctx.log("[S1] r30 미산출(데이터 공백) → 미참여"); return null
        if r30 <= THETA_LONG:
            ctx.log("[S1] 롱 조건 미충족 → 미참여 (선택적 참여)"); return null
        if not ctx.canEnter:
            ctx.log("[S1] 엔진이 진입 차단(손실한도/시간) → 미참여"); return null

        return {
            kind:      "BUY",
            symbol:    "SPY",
            orderType: "MARKET",
            sizePct:   min(RISK_PER_TRADE / STOP_PCT, MAX_POS_PCT),   // = min(0.50, 0.30) = 0.30
            stopLoss:  bar.c * (1 - STOP_PCT),
            reason:    `MIM r30=${r30}`
        }

    // ── (3) 청산은 엔진의 EOD 강제청산이 담당 (LOC 종가 체결 모사)
    return null
```

> **조기폐장일(13:00 ET 마감)**: `et == "15:30"` 하드코딩은 조기폐장일에 발동하지 않는다.
> **구현 시 `ctx.minutesToClose <= 30 and minutesToClose > 29` 조건으로 대체하라.** (엔진의 `SessionInfo.closeMs` 가 캘린더에서 오므로 자동 대응된다.) `09:59` 조건도 `bar.t - session.openMs` 기준 29~30분으로 대체한다.

### B.1.4 청산 규칙 — 실거래 (분 단위 확정)

| 시각 | 동작 | 실패 시 |
|---|---|---|
| **close−25m** (15:35 ET / 04:35 KST-EDT / 05:35 KST-EST) | **LOC 제출**: `POST /orders` `{side:"SELL", orderType:"LIMIT", timeInForce:"CLS", quantity:<정수>, price: formatUsPrice(lastPrice × 0.95)}` [확인됨, 스펙 v1.1.1: LIMIT+CLS = LOC, US 전용]. 지정가를 −5% 로 공격적으로 두어 체결확률을 극대화 (매뉴얼 §6.3) | `422 order-hours-closed` / `422 order-type-not-allowed` 수신 시 **즉시 close−10m 폴백으로 전환** |
| **close−10m** (15:50 ET) | **LOC 접수가 성공(PENDING)이면 아무것도 하지 않는다.** 접수 실패·REJECTED·주문 미발견이면 **미체결 전량 취소 → `MARKET` 전량 매도** | `409 already-*` 는 정상 흐름으로 무시 |
| **close+5m** (16:05 ET) | `GET /orders?status=CLOSED&from&to` 로 LOC 체결 확인. `execution.filledQuantity` 로 부분체결 확인 필수 | **미체결 잔량 발생 = 사고.** CRITICAL 알림 + **S1 자동 중단** + 익일 개장 시가 `MARKET` 청산 |

> **왜 S1만 close−10m 시장가 청산을 하지 않는가**: S1은 "마감 30분 구간의 수익"을 수확하는 전략이다. close−10m 에 시장가 청산하면 신호 구간의 **1/3을 버린다.** 대신 LOC 지정가를 −5% 로 두어 체결 확률을 최대화하고, 미체결을 사고로 취급한다.
> **LOC 접수 마감시각(cutoff) 은 스펙에 없다 [미확인]** — 미국 거래소는 통상 15:50 ET 전후로 제한하므로 close−25m 제출은 여유를 둔 값이다. **PoC 로 실측하라.**

**백테스트에서의 등가 처리**: `risk.exitBeforeCloseMinutes = 1` → 엔진이 15:59 봉 종가로 `EOD_LIQUIDATION` 청산. 종가 = LOC 체결가 가정이며, 이는 **LOC 체결률 100% 를 가정하는 낙관** 이다 (E장 명시).

## B.2 S2 — Concretum Noise-Area Breakout (보조 · 롱온리)

> Zarattini, Aziz & Barbon, *Beat the Market*, SSRN 4824172 / Concretum Group / TradingView "Concretum Bands"

### B.2.1 유니버스

**`SPY` 1종목.** S1과 동일. 밴드 계산에 14거래일 × 390분 = 5,460봉이 필요하며, `count=200` 기준 **28콜(5.6초)**, 이후 매일 2콜 증분 갱신.

### B.2.2 밴드 정의 (정확한 수식)

```
σ(HH:MM) = (1/N) × Σ_{d=1..N}  | close_d(HH:MM) / open_d(09:30) − 1 |

Upper_today(HH:MM) = open_today(09:30) × ( 1 + M × σ(HH:MM) )
```

- 당일 **시가 기준**으로 정규화하므로 **오버나잇 갭이 자동 보정**된다 [논문].
- 하단 밴드(Lower)는 **계산하되 사용하지 않는다** — 하단 이탈 신호는 숏이며 A.3.1 에 의해 구현 불가.

### B.2.3 파라미터 확정표

| 파라미터 | 기호 | **확정값** | 출처 |
|---|---|---|---|
| 룩백 | `N` | **14 거래일** | [논문] 기본 파라미터 |
| 변동성 배수 | `M` | **1.0** | [논문] 기본 파라미터 |
| 판정 격자 | `GRID` | **30분** — `10:00, 10:30, 11:00, 13:30, 14:00, 14:30, 15:00` (ET) | [논문] "30분마다 추세 방향 재확인" |
| 점심 배제 | — | **11:30~13:29 ET 신규진입 금지** (격자 11:30·12:00·12:30·13:00 제외) | [논문 — Örebro WP 14/2025] 변동성 09:35 0.08% → 13:05 0.03% |
| 마지막 신규진입 | — | **15:00 ET** | **[자체판단 · 검증대상]** — 15:30 이후는 S1 영역이라 중복 회피 |
| 하드 손절 | `STOP_PCT_S2` | **0.015 (1.5%)** | **[자체판단 · 검증대상]** — 논문의 스톱은 "밴드+VWAP 트레일링"이고 하드스톱은 없음 |
| 1트레이드 리스크 | `RISK_PER_TRADE` | **0.005** | **[자체판단 · 검증대상]** |
| 종목당 상한 | `MAX_POS_PCT` | **0.30** | **[자체판단 · 검증대상]** |

**자유 파라미터는 `N`, `M`, `STOP_PCT_S2` 3개.**

### B.2.4 의사코드

```
전략명: "concretum-noise"  ·  interval: "1m"  ·  symbols: ["SPY"]
init() 주입: sigmaByMinute[HH:MM]   // 최근 N=14 거래일 평균 절대이동폭. 매 세션 시작 시 갱신
warmupBars: 14 × 390 = 5460

onSessionStart(session):
    todayOpen = null;  vwapNum = 0;  vwapDen = 0

onBar(bar, ctx):
    et = etTimeLabel(bar.t)
    if et == "09:30": todayOpen = bar.o
    if todayOpen == null: return null

    // 당일 VWAP 누적 (정규장 봉만 — includeExtendedHours=false 이므로 자동 보장)
    vwapNum += ((bar.h + bar.l + bar.c) / 3) * bar.v
    vwapDen += bar.v
    vwap = vwapDen > 0 ? vwapNum / vwapDen : bar.c

    pos = ctx.position("SPY")

    // ── (A) 매 1분봉 청산 감시: VWAP 하향 이탈 [논문의 트레일링 정의]
    if pos and bar.c < vwap:
        return { kind:"EXIT", symbol:"SPY", orderType:"MARKET", reason:"VWAP 하향이탈" }

    // ── (B) 30분 격자에서만 진입/밴드복귀 판정
    if et not in GRID_ALL:  return null              // GRID_ALL = 10:00~15:00 의 모든 30분 격자
    upper = todayOpen * (1 + M * sigmaByMinute[et])

    if pos:
        if bar.c < upper:
            return { kind:"EXIT", symbol:"SPY", orderType:"MARKET", reason:"밴드 내 복귀" }
        return null

    // ── (C) 신규 진입
    if not ctx.canEnter:            return null
    if et in LUNCH_GRID:            return null      // {11:30, 12:00, 12:30, 13:00}
    if et > "15:00":                return null      // S1 영역 침범 금지
    if bar.c > upper and bar.c > vwap:
        return {
            kind:"BUY", symbol:"SPY", orderType:"MARKET",
            sizePct:  min(RISK_PER_TRADE / STOP_PCT_S2, MAX_POS_PCT),   // = min(0.333, 0.30) = 0.30
            stopLoss: bar.c * (1 - STOP_PCT_S2),
            reason:   `밴드 상단 이탈 ${et}`
        }
    return null
```

### B.2.5 청산 규칙 — 실거래

| 우선순위 | 조건 | 주문 |
|---|---|---|

### B.3.2 파라미터 확정표

| 파라미터 | 기호 | **확정값** | 출처 |

### B.3.3 의사코드 — 크로스섹션 랭킹 구현법 포함

```
전략명: "mind-the-gap"  ·  interval: "1m"  ·  symbols: [SPY, ...S&P500 자격통과 종목]
init() 주입 (전부 일봉 파생, 세션일 D 기준 D-1 값):
    prevClose[sym][date], atr14[sym][date], sma100[sym][date], adv20[sym][date], eligible[sym][date]

onSessionStart(session):
    rankedAtT = null

onBar(bar, ctx):
    et = etTimeLabel(bar.t)

    // ── (1) 09:30 봉에서 크로스섹션 랭킹을 "단 1회" 수행
    //     엔진은 (1)봉공개 를 그룹 전체에 먼저 수행하므로,
    //     이 시점 ctx.history(otherSymbol) 의 마지막 원소 = 동일 t 의 09:30 봉이다. (lookahead 아님)
    if et == "09:30" and rankedAtT != bar.t:
        rankedAtT = bar.t
        d = ctx.session.date

        // (1-a) 시장 전체 급락일 회피
        spy = lastBarAt("SPY", bar.t, ctx)
        if spy != null and (spy.o - prevClose["SPY"][d]) < -MKT_GAP_MULT * atr14["SPY"][d]:
            ctx.log("[S3] 시장 전체 급락일 → 당일 전면 미진입"); return null

        // (1-b) 후보 수집
        cands = []
        for sym in UNIVERSE:
            if sym == "SPY" or not eligible[sym][d]: continue
            b = lastBarAt(sym, bar.t, ctx)
            if b == null or b.t != bar.t: continue           // 당일 09:30 봉이 없으면 스킵
            if b.o < 10.00: continue                          // 가격 필터 재확인 (당일 실시간)
            gapAtr = (b.o - prevClose[sym][d]) / atr14[sym][d]
            if gapAtr < -GAP_MULT: cands.push({sym, gapAtr, open: b.o})

        // (1-c) 랭킹 및 신호 생성 (Signal[] 로 여러 종목 동시 주문)
        cands.sort(asc by gapAtr)
        picks = cands.slice(0, MAX_POS)
        ctx.log(`[S3] 후보 ${cands.length}종목 중 ${picks.length}종목 진입`)
        return picks.map(p => ({
            kind:"BUY", symbol: p.sym, orderType:"MARKET",
            sizePct:  PER_POS_PCT,
            stopLoss: p.open * (1 - STOP_PCT_S3),
            reason:   `gapdown ${p.gapAtr.toFixed(2)}×ATR`
        }))

    // ── (2) 보유 HOLD_MIN 분 경과 → 시간청산
    pos = ctx.position(bar.symbol)
    if pos != null and (bar.t - pos.openedAt) >= HOLD_MIN * 60_000:
        return { kind:"EXIT", symbol: bar.symbol, orderType:"MARKET", reason:"15분 시간청산" }

    return null
```

> **`lastBarAt(sym, t, ctx)`**: `ctx.history(sym)` 의 마지막 원소를 읽되 `.t == t` 인지 확인한다. 다른 시각이면 그 종목은 당일 데이터 공백이므로 스킵한다.
> **체결 타이밍**: 09:30 봉에서 신호 → 엔진이 09:31 시가 체결. 청산은 09:46 봉 판정 → 09:47 시가 체결 (실제 보유 ≈ 16분).
> **실거래는 더 빠르다**: `/prices` 배치 3콜(0.3초)로 09:30:03 에 시가 근사값을 얻어 즉시 시장가 진입. ⇒ **백테스트가 보수적** (D장 H8 로 정량화).

**백테스트 등가**: `risk.exitBeforeCloseMinutes = 10`.

# D. 백테스트 명세 (3번 에이전트 지시서)

## D.1 검증할 가설 — 전부 반증 가능한 형태

| ID | 가설 | 반증 조건 |
|---|---|---|
| **H1** | S1(MIM-Close, SPY, θ=0) 의 **비용차감 후 트레이드당 평균 순수익 > 0** | 단측 t검정 p ≥ 0.05 이면 **기각** |
| **H2** | H1 이 **2014-01-01 이후**(Gao et al. 표본 종료 이후) 구간에서도 유지된다 (알파 소멸 부재) | 2014 이후 구간에서 평균 순수익 ≤ 0 이면 **기각** — S1 폐기 |
| **H3** | S2(Concretum, N=14, M=1.0, 롱온리) 의 **비용차감 후 연율 Sharpe > 0.5** 이고 **MDD < SPY 매수후보유 MDD** | 둘 중 하나라도 미달이면 **기각** |
| **H4** | S3(Mind-the-Gap) 의 **비용차감 후 트레이드당 평균 순수익 > 0**, 표본 **≥ 100 트레이드** | 표본 부족이면 **결론 유보**(투입 금지), 평균 ≤ 0 이면 **기각** |
| **H5** | 인버스 ETF 우회로가 유효하다 — S1 의 r30 < 0 인 날에 (a)미진입 vs (b)`SH` 롱 을 비교했을 때 (b)의 net Sharpe 가 (a)보다 **유의하게 높다** | 유의하지 않으면 **인버스 ETF 경로 영구 폐기** (A.4.3 확정) |
| **H6** | 선택적 참여 논리가 유지된다 — S1 `participationRate ≤ 0.60`, 전 전략 `effectiveExposure ≤ 0.15` | 초과 시 **역풍 정면 노출 경보** → 전략 재설계 |
| **H7** | 비용 강건성 — `spreadBps` 와 `marketImpactBps` 를 **3배**로 올려도 각 전략의 net 총수익 **부호가 유지**된다 | 부호가 뒤집히면 해당 전략 **기각** (엣지가 비용 가정에만 존재) |
| **H8** | 폴링 지연 강건성 — "신호봉 종가 체결"(낙관) vs "다음봉 시가 체결"(엔진 기본, 현실) 의 차이가 net 기대값 **부호를 뒤집지 않는다** | 뒤집히면 **기각** (엔진 기본이 현실이므로 낙관 시나리오는 참고용) |
| **H9** | 세 전략의 **일간 net 손익 상관계수가 모두 \|ρ\| < 0.5** (분산 효과 존재) | 초과 시 해당 쌍 중 근거강도가 낮은 쪽을 **투입 보류** |
| **H10** | 당일청산 무결성 — `overnightTrades == 0` (`metrics.ts` 제공) | 1건이라도 발생하면 **엔진/전략 버그** — 성과 논의 이전에 수정 |

> **H1·H4 는 게이트다.** 통과 못 한 전략은 실거래에 투입하지 않는다.
> **H2 는 S1 의 존재 이유를 검증한다.** JFE 논문의 표본은 2013년까지이며, 발표(2018) 이후 알파 소멸은 정상적인 현상이다. 소멸이 확인되면 주력을 S2 로 교체한다.

  sizeImpactCoefBps:  0,

const COST_LARGECAP: CostParams = {

### D.3.3 환전 비용의 처리 — `applyFx = false` 를 base 로 두는 이유

우리 설계는 **USD 예수금을 사전 확보하고 그 안에서 회전**시킨다 (환전 API 가 없으므로 [확인됨] 봇이 스스로 환전할 수도 없다). 따라서 매 거래마다 환전 스프레드를 물지 않는다. 대신:

- `applyFx = false` 를 base case 로 하고,
- **연 1회 진입/청산 환전 비용(왕복 20bp)을 성과 리포트에 별도 항목으로 차감 표기**하며,
- `applyFx = true` 버전을 **민감도 시나리오로 함께 산출**한다.

### D.3.4 왕복 비용 하한 산술 (base case)

```
S1/S2 (SPY, 왕복):
  위탁수수료   0.10% × 2회 = 20.0 bp    ← ★ 가장 큰 항목이며 [미확인]. 실측 필수
  half-spread  0.5 bp × 2회 =  1.0 bp
  시장충격     2.0 bp × 2회 =  4.0 bp
  SEC + TAF (매도만)        ≈  0.3 bp
  ────────────────────────────────────
  왕복 총비용               ≈ 25.3 bp

S3 (대형주, 왕복):
  위탁수수료 20.0 + half-spread 3.0 + 충격 6.0 + SEC/TAF 0.3  ≈ 29.3 bp
```

> **이 표가 이 프로젝트에서 가장 중요한 숫자다.**
> Barber & Odean 의 대만 데이트레이더 **일평균 −23.9bp** 는 사실상 왕복 거래비용과 같다.
> **평균적 데이트레이더의 손실 = 거래비용**이다. 전략이 25~30bp 를 이기지 못하면 정확히 이 결과가 나온다.
> **`commissionRate` 가 전체 비용의 80% 를 차지한다.** PoC 최우선 항목이 `GET /api/v1/commissions` 실측인 이유다.

### D.5.2 IS / OOS 분리

```
전체 표본을 시간순으로 정렬
  ├─ In-Sample  (앞 70%)  : 파라미터 선택은 여기서만. 몇 번을 봐도 된다.
  └─ Out-of-Sample (뒤 30%) : ★ 단 1회만 평가한다.

OOS 를 보고 파라미터를 바꾸면 그 순간 OOS 는 IS 가 된다.
OOS 평가는 전략당 1회로 제한하고, 평가 시점과 결과를 로그에 append-only 로 기록한다.
```

**S1 은 추가로 H2 를 위한 자연 분할을 함께 본다**: 1993–2013(논문 표본) vs 2014–현재(표본 밖). 이 분할은 IS/OOS 와 독립적으로 리포트한다.

### D.5.3 파라미터 안정성 검사 (peak sharpness)

IS 최적 파라미터 주변 **±1 스텝**의 성과를 함께 본다.

```
IF (최적점 Sharpe) / (인접 격자점 Sharpe 평균) > 1.5   →   기각 (뾰족한 봉우리 = 노이즈 적합)
```

**[자체판단 · 검증대상]** — 근거는 1번 문서의 tosindicators 결과("25개 파라미터 조합 중 17개(68%)가 벤치마크 초과")다. **넓은 고원(plateau)이 강건성의 증거**이고, 승률 절대값보다 훨씬 신뢰할 만한 정보다. 따라서 **"전체 조합 중 합격선을 넘는 비율"을 리포트 필수 항목**으로 둔다.

### D.5.4 다중검정 통제

전략 3개 × 파라미터 71조합 = 다중검정 문제가 발생한다. Bonferroni 보정 대신 **"OOS 는 전략당 단 1회 평가"** 규칙으로 통제한다. IS 에서의 t통계량은 **탐색적 지표로만 취급**하고 의사결정 근거로 쓰지 않는다.

### D.5.5 최소 표본 규칙

- 전략별 **최소 100 트레이드**. 미만이면 **결론 유보** (합격도 불합격도 아님, 투입 금지).
- OOS 구간 트레이드 수가 **30 미만**이면 OOS 판정을 신뢰하지 않고 표본 기간을 늘린다.

> **롱온리 강제 + 인트라데이 평균수익 ≤ 0 의 조합이 이 시스템의 가장 근본적인 리스크다.**

>

## E.5 아키텍처 상의 강제 사항 (재확인)

- **Vercel 배포본에 주문 툴을 두지 않는다.** 고정 IP 부재(403 `edge-blocked`) + **"client 당 토큰 1개, 재발급 시 이전 토큰 즉시 무효화"** [확인됨] 때문에 서버리스는 구조적으로 부적합하다.
- **주문은 고정 IP 상시 서버(VPS)의 단일 프로세스에서만** 낸다. 토큰 발급은 in-flight 프로미스 공유로 직렬화한다.
- **강제청산은 메인 봇과 독립된 프로세스에서 한 번 더 트리거**한다. `clientOrderId` 멱등성(10분 유효) 덕분에 중복 실행이 안전하다.
- **서버측 스톱로스가 존재하지 않는다** [확인됨]. **봇이 죽으면 손절도 죽는다.** 하트비트 워치독이 끊기면 즉시 알림 + 청산 트리거를 건다.
- 소수점(`orderAmount`) 주문은 **절대 사용하지 않는다** — `quantity` 가 정수만 허용되어 소수 잔량을 결정론적으로 청산할 수 없다 [확인됨, 스펙 §3.8].
